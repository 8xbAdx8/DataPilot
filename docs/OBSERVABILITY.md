# 配额与执行诊断

## 如何查看

工作台执行分析后，展开“执行详情”，可核对请求 ID、分段耗时与 Token 来源；刷新后通过历史恢复的仍是当次分析诊断。旧历史没有采集数据时不补写耗时或 Token。

每次 HTTP 响应均返回服务端生成的 `X-Request-ID`，不信任客户端传入的同名头。分析元信息的 `request_id` 指向创建分析时的请求；以后 GET 详情的响应头有新的请求 ID。出现错误时可把 ID 提供给管理员，避免粘贴敏感问题或数据。

本机 Uvicorn 控制台包含每行一个的业务 JSON 事件。容器里可查看：

```powershell
docker compose logs --no-color --tail 100 backend
```

默认关闭 Uvicorn 原始访问日志，避免 URL 查询参数进入日志。JSON 只包含固定字段：UTC 时间、事件、请求 ID、内部用户/分析 ID、路由模板、HTTP 方法、状态码、错误代码、耗时、响应字节数及有界用量。未知路由记录 `<unmatched>`。不记录原始 URL、查询参数、Cookie、用户名、密码、Key、上传文件名、问题、SQL、查询行或异常正文。代理、第三方库或操作者自行启用的调试日志应单独审核。

`http_request` 覆盖成功、认证/校验失败、限流和服务错误。`analysis_completed` 对应实际进入分析流程的结果；被配额拒绝的请求只产生 HTTP 事件，没有分析结果。数据库提交失败时记录 `storage_unavailable`，不会记录成功；业务历史可能仍是 running，由保留清理命令恢复中断状态。

Compose 为 backend 的 Docker 日志设置 `max-size=10m`、最多 3 个轮转文件；本机重定向日志的轮转由操作者负责。内部 ID 属于可关联的业务元信息，仍应限制日志访问。

## 指标含义

| 字段 | 测量范围 |
| --- | --- |
| HTTP `duration_ms` | 服务端 ASGI 请求处理耗时，包括路由和响应处理；不等于用户网络延迟 |
| 分析 `duration_ms` | 初始历史提交后，从模型步骤开始到生成/保存结果文件或发生失败；不含最终数据库提交 |
| `timings_ms.provider` | Provider 调用及模型结构化输出解析 |
| `timings_ms.sql_guard` | SQL AST 与真实 Schema 验证 |
| `timings_ms.query` | DuckDB 子进程启动、查询与结果传输 |
| `timings_ms.persist` | 图表/事实生成、序列化和结果快照文件写入；不含最终业务事务提交 |
| HTTP `response_bytes` | ASGI 响应体字节，不含头部和代理后的网络压缩 |

耗时向下取整为毫秒，0 可以表示不足 1 ms；缺少阶段表示未执行或未采集，不能替换成 0。阶段失败也记录已花费的时间。所有指标是实际请求测量，不是容量或并发吞吐承诺。

## Token 与费用边界

兼容适配器从 HTTP 响应外层 `usage` 获取 `prompt_tokens`、`completion_tokens` 和 `total_tokens`，不接受模型 SQL JSON 自报的统计。协议参考 [DeepSeek 官方响应定义](https://api-docs.deepseek.com/api/create-chat-completion/)。

- `source=provider`：提供商上报的非负整数；缺少的项保持 null，不反推未知项。
- `source=mock`：确定性模板没有调用模型 API，Token 明确为 0。
- `source=unavailable`：未上报、格式错误、负数、类型错误或已知总量矛盾，计数保持 null。模型不可用或超时时也不会把未知用量记为免费。

即使模型内容无效或 SQL 被安全拒绝，已上报的用量仍保留。只校验 HTTP 合同并不代表真实模型已验证；当前没有真实 API 凭据。

Token 不能直接当作账单：模型价格、缓存命中、计费规则与币种可能不同。本阶段不预置价格，不估算费用，也没有验证提供商实际扣款。业务元信息继续保存问题与 SQL，诊断日志只记录上述白名单字段。

## 限流语义

| 环境变量 | 默认值 | 范围 |
| --- | --- | --- |
| `ANALYSIS_REQUESTS_PER_WINDOW` | 30 | 每用户分析请求额度，1–1000 |
| `UPLOAD_REQUESTS_PER_WINDOW` | 10 | 每用户上传请求额度，1–1000 |
| `RATE_LIMIT_WINDOW_SECONDS` | 60 | 窗口秒数，1–3600 |

PostgreSQL 的 `(user_id, scope)` 主键与条件 UPSERT 原子检查、递增计数；使用数据库时间。窗口从首次放行开始，到期后的首个请求重置，用户和动作之间独立；多个 API 进程共享配额，重启应用不会清空。各实例应使用相同配置。SQLite 仅用于隔离测试，不作为部署数据库。

超过额度返回 `429 rate_limited`、整数 `Retry-After` 秒数和请求 ID。前端显示等待建议，不自动重试。失败的模型请求、安全拒绝和已进入解析的无效上传会消耗配额；未登录、无权访问、无效问题或不支持扩展名的请求不会进入对应业务配额。上传限流发生在格式扩展名确认后、导入前，不能替代网络层的带宽和请求体限制。

分析配额与 running 历史在同一事务提交，上传配额在解析前提交；计数存储失败时返回 503，不绕过限流继续执行。限流前仍强制身份与所有权验证。每日显式 retention CLI 可清理已过期配额行；未执行清理也会按到期时间正确重置。

本阶段覆盖分析、上传两个重操作。GET、匿名网络请求和所有入口的全局/IP 速率仍需网关控制；登录沿用每账户 15 分钟内 5 次失败的独立策略。窗口边界可能短时间容纳前后两个窗口的请求，这不是严格滑动窗口或并发数上限；DuckDB 的执行并发限制继续生效。

## 验证入口

`test_rate_limits.py` 验证拒绝前不调用 Provider/导入器、失败消耗额度、过期重置、用户/动作隔离、数据库不可用时拒绝执行。真实 PostgreSQL 专项用 8 个独立会话争抢 3 个配额，断言恰好 3 次成功、5 次 429，不用进程内锁代替数据库原子性。

`test_observability.py` 核对响应头、历史与日志关联；把敏感哨兵放进 URL、头、文件名、问题、结果和异常后断言它不进入业务事件；验证失败阶段、数据库提交失败与旧历史兼容。Provider 合同测试区分有效、部分和无效 usage。浏览器用真实 Mock 失败耗尽额度，再验证 429、等待提示与没有自动重试。
