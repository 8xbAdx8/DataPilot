# 五分钟求职演示与验收边界

## 启动与演示

按 README 启动原生服务，或按 OPERATIONS 运行 Docker Compose。管理员创建自己的账户，登录后演示；保持 `LLM_PROVIDER=mock` 无需申请 Key。工作台默认端口 3000。旧版演示数据需显式分配归属，或登录后重新上传合成样例。

1. 上传项目自带的合成数据 `data/examples/sales.csv`。核对 8 行、字段类型、缺失值和预览。
2. 问“这个数据集有多少行？”，SQL 的 COUNT 与实际结果应为 8。
3. 问“按 region 统计 revenue 总和”，检查 SQL、表格、柱状图：华东 67,000、华北 17,700、华南 11,000。各视图来自同一份 DuckDB 结果。
4. 下载 CSV，核对数值；刷新后通过分析历史恢复结果。用 `SUM` 搜索 SQL，再筛选“成功”。清空或重置筛选可恢复全部记录。
5. 问一个 Mock 不支持的问题，例如“预测下个月的销售额”。应显示明确失败，并能筛选到失败历史；不生成预测或成功图表。
6. 展示 SQL 安全回归测试中的恶意输入及“执行器从未被调用”的断言。Mock 不会生成危险 SQL，不能用聊天窗口里的拒绝回答代替 AST 安全验证证据。
7. 退出后使用另一个账户登录，原数据集和历史不应出现。展示双用户回归中对已知数据集、分析和导出 UUID 的访问均返回 404；这验证后端授权，不只是侧栏隐藏。
8. 展开“执行详情”，核对请求 ID 与日志中的同一条分析、各阶段耗时，以及 Mock Token 为 0。真实提供商未上报有效 usage 时应显示未知；不要把 Token 当作实际账单。
9. 可选账户演示：用两个浏览器会话登录自己的合成账户，打开“账户安全”撤销另一会话并验证其变为 401；随后改密，两个旧会话均失效，只有新密码能登录。忘记密码由管理员 CLI 重置，不在公开页面恢复。

## 面试中解释设计

- **为什么前后端分开？** Next.js 管理上传/提问/结果交互，FastAPI 复用 Python 数据生态，强制校验在后端；两者独立构建测试。
- **为什么两种数据库？** PostgreSQL 负责元信息和事务；DuckDB 处理上传数据的聚合。查询进程没有平台数据库连接，模型 SQL 只能访问当前 `data` 表。
- **为什么不能只用提示词？** 模型输出不可信。SQLGlot AST、真实 Schema 和函数白名单先检查；受限子进程再控制执行时间、内存和输出大小。
- **为什么先用 Mock？** 它让演示和安全测试可重复，且查询仍由真实 DuckDB 执行。真实模型的网络合同测试、凭据验收必须另外记录。
- **为什么历史搜索不调用模型？** 它是普通平台业务查询，SQLAlchemy 绑定关键词即可；搜索文本不能扩大数据访问范围。
- **为什么配额放 PostgreSQL？** 现有业务库能用条件 UPSERT 原子检查和递增，多进程共享额度；暂不增加 Redis。限流回归用独立数据库会话验证，前端不承担限制权限。
- **为什么改密还要数据库锁？** 旧密码登录可能与重置同时发生。统一锁序和锁后刷新使排队请求看到最新密码和撤销状态；真实 PG 并发回归验证这种交错，不能用 SQLite 单连接成功来推断。

2026-10-20 已通过 DeepSeek `deepseek-flash` 的单个真实 API / AST / DuckDB 行数用例（1 passed，结果 3），并确认运行中的前后端配置已切换。该结果不是模型准确率评测；真实模型的分组分析、图表和浏览器完整闭环尚未单独验收。当前支持账户、密码修改/管理员重置、会话管理和用户数据所有权，尚无自助找回、MFA、组织共享或完整公网防滥用措施。没有测量线上容量、并发吞吐或真实模型准确率，不应在简历中编造这些指标。Windows Docker 引擎问题仍未修复，Linux 容器验收按提交查看 CI。

可据实描述项目：实现支持 CSV/XLSX 的自然语言分析平台，使用 SQL AST 校验和受限 DuckDB 执行真实查询，提供结果可视化、历史检索和 CSV 导出，并通过 PostgreSQL 集成测试及 Docker Compose CI 验证。
